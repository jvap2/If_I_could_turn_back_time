Software Process Flowchart — Gaussian 4-bit (GF4) Quantized Inference

Main steps performed by the software. Phase A prepares the model once; Phase B runs at inference, once per network layer.

Phase A — Model Preparation & Quantization  (performed once)

1Input: trained neural network & a small calibration dataset
2For each linear layer, generate a randomized orthogonal (Hadamard) rotation
3Forward the calibration data; collect statistics of the rotated activations per layer (second-moment / Hessian and mean μ)
4Rotate each layer's weights by the Hadamard transform and quantize the rotated weights to 4 bits (per-block scaled), stabilizing the fit with adaptive condition-number Hessian damping
5Compute the activation mean-correction (μ) and the corresponding bias-correction term
6Store the compressed model: 4-bit weights, rotation, per-block scales, μ, bias-correction

Phase B — Inference  (repeated for each layer)

7Receive the layer's input activations
8Apply the Hadamard rotation to the activations
9Subtract the activation mean μ
Core step — GF4 look-up table10Quantize the rotated activations to 4 bits with the GF4 Gaussian codebook: normalize by a per-block scale, then map each value to the nearest of 8 Gaussian-distributed magnitude levels + a sign bit (a 4-bit code)
11Perform the multiply-accumulate directly in the 4-bit domain (4-bit weights × 4-bit activations) via table-look-up decode
12Add the bias-correction and the layer bias to form the layer output
13More layers remaining?

↻ Yes → advance to next layer (return to step 7)

No → output the network's result

The GF4 look-up table (step 10) is the central inventive step; the surrounding rotation, per-block scaling, and mean/bias corrections place it in context. Steps 3–5 (calibration & condition-number-stabilized weight fit) enable robust 4-bit operation across model scale.
